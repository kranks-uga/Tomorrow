# Serial-порт COM1 (`src/serial.rs`)

Независимый от экрана канал вывода: boot-лог, паники и «unknown syscall»
уходят в UART. Экран показывает только последнюю строку и замирает вместе с
ядром; serial-лог остаётся снаружи — в терминале QEMU или на USB-TTL.

Реализована **только передача (TX)**. Приём, прерывания и DMA не используются.

---

## 1. Железо

Стандартный 16550-совместимый UART по адресам COM1 (`0x3F8`–`0x3FF`).
Регистры (смещение от базы):

| Смещение | Чтение | Запись | Назначение |
|---:|---|---|---|
| `+0` | RBR | THR | принятый / передаваемый байт (при `DLAB=1` — младший байт делителя) |
| `+1` | IER | IER | разрешение прерываний (при `DLAB=1` — старший байт делителя) |
| `+2` | IIR | FCR | идентификатор прерывания / управление FIFO |
| `+3` | LCR | LCR | формат линии, бит 7 — `DLAB` |
| `+4` | MCR | MCR | DTR/RTS/loopback |
| `+5` | LSR | — | статус: бит 5 — THR пуст, можно писать |

Инициализация (`serial::init`):

```
IER = 0x00          прерывания выключены
LCR = 0x80          DLAB=1
DLL = 0x01, DLM = 0  делитель 1 → 115200 бод (базовая частота 115200)
LCR = 0x03          DLAB=0, 8 бит, без паритета, 1 стоп-бит (8N1)
FCR = 0xC7          FIFO включён, сброс, порог 14 байт
MCR = 0x03          DTR | RTS
```

Запись байта — опрос `LSR.THRE` с ограничением `TX_SPIN_LIMIT`
(1 000 000 итераций). Если порт не отвечает, байт теряется, но загрузка
не зависает: на плате без COM1 `LSR` читается как `0xFF`, и ожидание
заканчивается сразу.

`\n` автоматически превращается в `\r\n` — иначе терминал оставляет курсор
в начале строки.

## 2. API

```rust
serial::init();                       // один раз при старте
serial::_print(format_args!(...));    // через макросы ниже
serial::try_print(format_args!(...)); // не блокируется, для паники
```

Макросы (экспортируются в корень crate):

```rust
sprint!("ticks={}", n);      // без перевода строки
sprintln!("pid={} fd={}", p, fd);
```

Для паники есть только неблокирующий вариант: `try_print` берёт лок через
`try_lock`, и если лок уже занят (паника внутри печати), строка пропускается.
Блокирующий `_print` в панике мог бы дать вечный дедлок — ровно тот
«замёрзший экран», от которого serial и спасает.

### Лок

Один `spin::Mutex<()>` на весь порт: boot-лог, шелл и паника не перемешивают
байты. **В обработчиках прерываний serial использовать нельзя** — если
прерывание придёт, пока прерванный код держит лок, обработчик встанет
навсегда. Поэтому:

- `bootlog!` — только для загрузки (`kernel_main`);
- сторож `GDT3` в `timer_do_switch` печатает только на экран (`kprint!`).

## 3. Куда подключено

| Место | Что пишет |
|---|---|
| `kernel_main` (начало) | `serial::init()`, заголовок `--- Tomorrow OS serial log ---` |
| `bootlog!` | вехи загрузки: `IDT ok`, `PMM ok`, `HEAP ok`, `Syscall ok`, `APIC ok`, `Scheduler ok` … |
| `panic` | `PANIC at file:line` через `try_print` |
| `syscall_handler` | `unknown syscall N` перед возвратом `ENOSYS` (задел для трека F) |

`bootlog!` = `kprint!` + `sprint!`: сообщение одновременно на экран и в UART.
Так экранный вывод не меняется, а serial получает полную картину.

## 4. Как читать лог

### QEMU

`run.sh` уже передаёт `-serial stdio`, вывод идёт в тот же терминал:

```bash
./run.sh
```

Headless-проверка (без окна), лог в файл:

```bash
timeout 30 qemu-system-x86_64 \
    -machine q35 \
    -bios /usr/share/edk2/x64/OVMF.4m.fd \
    -cdrom tomorrow.iso -m 256M \
    -display none -serial file:/tmp/serial.log -no-reboot
cat /tmp/serial.log
```

### Реальное железо

USB-TTL-кабель, 115200 8N1, без flow control:

```
плата TX  →  адаптер RX
плата GND →  адаптер GND
```

Только TX: адаптер TX к плате подключать не нужно.

## 5. Ограничения

- **Только вывод.** Ввод с serial (`sys_read(fd 0)` из трека B) не реализован.
- **Опрос, не прерывания.** На каждый байт — цикл по `LSR`; при 115200 это
  ~87 мкс на байт. Для лога нормально, для потока данных — нет.
- **Скорость зашита** (делитель 1, 115200). Настройка через аргумент —
  когда появится вторая плата с другим кварцем.
- **Один порт.** COM2–COM4 не поддержаны.
- **Лок не реентерабельный** — см. правило про обработчики прерываний.
